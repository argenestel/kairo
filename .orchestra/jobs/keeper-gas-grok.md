# Job: make the EVM keeper gas-efficient (Grok)

You own montions-base/bots/src/evm-keeper.ts (+ a test file for it under montions-base/bots/test/). Problem: refreshVault() refreshes series round-robin regardless of whether anything changed; on Base Sepolia one MakerVault.refresh costs ≈ 0.00007 ETH (mostly L1 data fee), so the default (40 per 15 s) burns ≈ 0.7 ETH/hour. Currently it runs throttled with EVM_REFRESH_LIMIT=1, EVM_KEEPER_INTERVAL_MS=120000.
Change the policy: read state in batched eth_calls (multicall) — for each Open series compute the Quoter fair tick (or read it via the Quoter snapshot) and the vault's current best quotes; refresh only when (a) |fair − midpoint of the vault's current quotes| ≥ EVM_REFRESH_MIN_TICKS (default 2), or (b) the vault has no quote on a side (filled/cancelled), or (c) the series is new; never more than EVM_REFRESH_LIMIT per tick (default 4); never refresh inside the vault's min time-to-expiry. Keep record/resolve/redeem/create behaviour unchanged. Add a gas budget guard: EVM_MAX_ETH_PER_DAY (default 0.01) tracked in a small state file; when exceeded, only do resolve/record/redeem. Log a per-tick summary incl. estimated ETH spent. Unit-test the selection logic with fixtures. Don't start long-running processes; run `pnpm --dir bots test` (or the project's test command) and one `--once --dry-run` pass against Base Sepolia with DEPLOYMENT=deployments/84532.json CHAIN_ID=84532 (no key needed for dry-run, or use a read-only path).
